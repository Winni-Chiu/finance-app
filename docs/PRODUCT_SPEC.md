# 財務管家 APP 產品規格

- 文件狀態：需求基線草案（待產品確認）
- 版本：0.1
- 更新日期：2026-09-23
- 範圍：記錄目前對話中已明確確定的需求，並標示尚未提供的細節；本文件不代表尚未確認的實作決策。

## 1. 產品目的與範圍

財務管家 APP 用於記錄個人消費，管理支付方式與信用卡帳期，查看消費清單及統計，並支援 Money Manager `.mmbak` 資料匯入和資料備份還原。

本規格僅以目前明確提供的需求建立基線。專案工作區目前除了 `.git` 外沒有產品文件或程式碼可供交叉確認。因此，除下文「已確認」規則外，畫面欄位、統計口徑、匯入欄位對應等均列為待確認，不視為已定案。

## 2. 功能需求

### 2.1 消費管理

- APP 須支援建立消費交易，並提供消費建立後的編輯頁。
- 編輯頁提供「移至下月帳」操作；新增消費頁不得出現此操作。
- 「移至下月帳」須實際變更交易日期為下一個帳單週期的第一天，而非只改變顯示月份或分類。
- 首次移動時須保留原始消費日期。之後再次移動，原始消費日期仍是第一次消費日期，不得以最近一次移動前的日期覆蓋。
- 「複製成新消費」須建立一筆新的交易，日期設為今天；不得只是修改或重新使用來源交易。
- 全部消費頁須列出所有支付方式的消費，現金也必須包含在內。

### 2.2 帳單週期及信用卡

- 信用卡須能依結帳日判定帳單週期。
- 結帳日為 23 日時，帳期範例已確定為：9/23～10/22、10/23～11/22。區間包含起訖日，並以結帳日作為每一期的第一天。
- 信用卡頁的比較重點為「上月／本月」；不需要顯示下月金額。
- 信用卡資料欄位、每卡個別帳單資訊、付款到期日、信用額度、循環餘額及月份比較的精確金額口徑尚待確認。

### 2.3 支付方式

- 消費可關聯支付方式。
- 支付方式至少涵蓋信用卡及現金，且全部消費頁不可排除現金交易。
- 其他支付方式種類（例如簽帳金融卡、轉帳、電子支付）及其設定方式尚待確認。

### 2.4 統計表

- APP 須提供消費統計表功能。
- 統計表的維度、篩選條件、時間區間、圖表形式、分類與支付方式的統計口徑、退款處理方式及匯出方式尚未確認；不得在實作時假設為已定案。

### 2.5 Money Manager `.mmbak` 匯入

- APP 須支援匯入 Money Manager 的 `.mmbak` 備份檔。
- 匯入映射、支援的 Money Manager 版本及檔案格式細節、重複交易判定、匯入前預覽、錯誤處理、部分成功策略及是否匯入帳戶/類別/支付方式等尚待確認。
- 匯入不得在未確認的情況下默默覆蓋既有資料；匯入採新增、合併或取代的策略需產品決定。

### 2.6 備份與還原

- APP 須提供資料備份及還原能力。
- 備份範圍、檔案格式、儲存位置、加密方式、還原前確認、同名資料衝突處理與跨版本相容性尚待確認。
- 還原是否覆蓋或合併現有資料尚未定案；介面與流程須清楚呈現其效果後再實作。

## 3. 資料結構基線

以下描述的是由已確認功能所需的概念資料及必要語意，不是已核定的資料庫 schema 或欄位型別。

### 3.1 消費交易（Expense / Transaction）

| 概念欄位 | 說明 | 狀態 |
|---|---|---|
| 交易識別碼 | 區分每筆交易；複製時建立新識別碼 | 必要語意 |
| 交易日期 | 當前交易日期；「移至下月帳」會將它更新為下一帳期首日 | 已確認 |
| 原始消費日期 | 第一次消費日期；首次移動時保留，重複移動不得改寫 | 已確認 |
| 金額 | 消費金額 | 待確認型別、幣別及退款表示法 |
| 支付方式 | 關聯至支付方式；可為現金或其他方式 | 已確認概念 |
| 信用卡/帳期關聯 | 若使用信用卡，供信用卡頁與帳期操作使用 | 由功能推導；具體 schema 待確認 |
| 備註、分類、商家等 | 常見交易資訊 | 是否需要及欄位內容待確認 |

原始消費日期的儲存方式尚未指定；實作需提供永久保留該值的資料語意，不能只依賴不可追溯的畫面狀態。未移動交易是否將原始消費日期設為交易日期、以及時區/跨日規則，待確認。

### 3.2 支付方式（Payment Method）

需要能識別支付方式，並至少表達信用卡與現金。支付方式的名稱、種類、啟用/封存狀態及與帳戶的關係尚待確認。

### 3.3 信用卡（Credit Card）

信用卡需具備足以判定帳單週期的結帳日。卡片名稱、發卡資訊、到期日、額度、付款方式等欄位尚待確認。結帳日的合法範圍，以及月份天數不足時如何處理亦待確認。

### 3.4 帳單週期（Billing Cycle）

至少需要依信用卡結帳日計算期首與期末。結帳日 23 日的已確認區間為 9/23 至 10/22、下一期 10/23 至 11/22。日期區間包含起訖日；其他結帳日的一般化算法、短月份與閏年邊界尚待確認。

## 4. 帳單週期操作規則

### 4.1 「移至下月帳」

1. 操作位置：消費建立後的編輯頁。
2. 新增消費頁：不顯示此操作。
3. 操作結果：將該筆消費的「交易日期」實際改為下一個帳單週期第一天。
4. 原始日期：第一次執行時記錄原始消費日期；若此欄已存在，往後重複移動不得覆寫。
5. 帳期判定：依該筆消費所屬信用卡/帳單週期計算；結帳日 23 日的日期範例依本文件第 2.2 節。
6. 重新操作時「下一個」帳期的參照日期、是否可復原、是否提示使用者，以及無信用卡交易的處理方式尚待確認。

### 4.2 複製成新消費

- 建立新的交易識別碼與新交易。
- 新交易日期設為操作當天（今天）。
- 來源交易不可被日期更新或被新交易取代。
- 其他欄位是否沿用來源交易（如金額、支付方式、備註、分類）尚待確認。

## 5. 畫面與操作規則

### 5.1 全部消費頁

- 顯示所有支付方式的消費，包含現金。
- 清單排序、分頁、篩選、欄位、空狀態與金額呈現方式尚待確認。

### 5.2 新增消費頁與編輯頁

- 新增頁可建立交易，不得顯示「移至下月帳」。
- 已建立消費的編輯頁可使用「移至下月帳」。
- 編輯頁是否提供複製成新消費、刪除、撤銷或確認提示等其他操作尚待確認。

### 5.3 信用卡頁

- 比較期間以「上月／本月」為主。
- 不顯示下月金額。
- 上月及本月的日期邊界、交易金額採用交易日期或帳單歸屬日、是否含未入帳交易等統計口徑尚待確認。

### 5.4 其他頁面

統計表、匯入、備份與還原的導覽位置、流程與文案尚待確認。

## 6. 待產品確認事項

以下項目目前沒有足夠資訊，正式實作前需確認：

1. 新增消費及交易編輯的完整欄位、類別/帳戶模型、幣別與金額精度。
2. 交易日期與原始消費日期的初始值、原始日期是否可由使用者編輯，以及時區規則。
3. 各結帳日的一般帳期算法、短月份（例如 29–31 日）與閏年處理；移動操作反覆執行的期別計算基準。
4. 信用卡頁「上月／本月」的明確期間及統計口徑。
5. 支付方式清單及自訂方式規則。
6. 統計表的項目、篩選、圖表、統計口徑與匯出需求。
7. `.mmbak` 匯入格式/欄位映射、重複資料策略、預覽及失敗處理。
8. 備份/還原格式、範圍、覆蓋或合併策略與安全提示。
9. 刪除、退款、取消移動、資料同步、權限與離線需求。

## 7. 驗收基線

在上述待確認事項未定案前，可先以明確規則作為最低驗收條件：

- 結帳日 23 日時，9/23–10/22 與 10/23–11/22 被判定為連續且不重疊的帳期。
- 「移至下月帳」只出現在已建立消費的編輯頁，不出現在新增頁。
- 執行移動後，交易日期等於下一個帳期第一天。
- 首次移動後原始消費日期可讀取；再次移動不改變第一次記錄的原始日期。
- 複製操作產生新交易，日期為今天，來源交易保留。
- 全部消費頁包含現金與其他支付方式的交易。
- 信用卡頁提供上月/本月比較，不需要下月金額。
- `.mmbak` 匯入及備份/還原功能需存在；其資料映射與衝突驗收方式須待產品確認後補充。
